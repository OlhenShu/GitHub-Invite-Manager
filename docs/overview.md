# Огляд

GitHub Invite Manager спрощує роздачу лабораторних робіт: ментор не створює десятки репозиторіїв і запрошень вручну в UI GitHub.

## Що можна зробити

1. **Створити репозиторії з template-репозиторію**
   - у організації, або
   - під особистим GitHub-акаунтом (поле організації порожнє).
2. **Запросити студентів як collaborators**
   - у щойно створені репо;
   - у вже існуючі репо (особисті або організаційні).

Режими запрошення:

- **Individual** — `репо[i] → студент[i]` (кожному своє репо).
- **Team** — кілька студентів на одне спільне репо (ручне призначення).

## Стек

- Бекенд: Java 17, Spring Boot 3, GitHub REST API.
- Фронтенд: React, Vite, TypeScript, Tailwind.
- Токен живе лише в пам’яті браузера на час сесії. Його не пишуть у `localStorage`, cookies чи базу. Браузер надсилає його бекенду заголовком `X-GitHub-Token`, бекенд викликає GitHub.

## Потік даних

```text
Браузер (токен у React state)
    → POST/GET /api/...  (заголовок X-GitHub-Token)
    → Spring Boot
    → api.github.com
```

Створення з шаблону: `POST /repos/{template_owner}/{template_repo}/generate`.  
Запрошення: `PUT /repos/{owner}/{repo}/collaborators/{username}`.

Для особистих репозиторіїв GitHub може відхилити поле `permission` (воно офіційно для org-репо). Бекенд у такому разі повторює запрошення без цього поля.
