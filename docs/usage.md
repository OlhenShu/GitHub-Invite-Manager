# Як користуватись

На головній сторінці три картки: створення репо, запрошення, копіювання issues. Оберіть потрібну, токен можна ввести на головній або вже всередині розділу. Кнопка логотипа або **Back to home** повертає на головну.

## Створення репозиторіїв

Вкладка **Create Repositories**.

1. **Template owner** і **Template repository** — шаблон (особистий або org). У налаштуваннях шаблону має стояти **Template repository**. Після успішного створення браузер запам’ятовує до 80 шаблонів і 80 організацій (localStorage, без токена). Список **Recent templates** групує їх за owner і має пошук, щоб не роздувати форму на десятки спринтів.
2. **Target organization**
   - порожньо → репо створюються під вашим акаунтом;
   - `my-org` → репо в організації.
3. **Visibility:** private / public. **Internal** доступне лише коли вказана організація.
4. **Include all branches from template** — якщо вимкнено, GitHub копіює лише default-гілку; увімкніть, коли в шаблоні кілька гілок.
5. Іменування:
   - **Pattern + Counter** — `lab-01`, `lab-02`, …;
   - **Custom List** — список GitHub-юзернеймів студентів; ім’я репо = `{template}-{username}`.

Після успішного створення повні імена `owner/repo` підхоплюються на вкладку Invite.

## Запрошення студентів

Вкладка **Invite Collaborators**.

### Звідки взяти репозиторії

Можна комбінувати:

1. Репо **з цієї сесії** створення.
2. **Existing repositories**
   - **My account** — особисті репо, без організації. **Load from GitHub**.
   - **Organization** — вказати org і завантажити її репо.
3. **Additional repositories** — вручну, по одному `owner/repo` на рядок:

   ```text
   yourname/lab-01
   my-org/lab-02
   ```

### Кого запрошувати

Список GitHub-юзернеймів (по одному на рядок, `#` — коментар). Можна завантажити `.txt`.

### Режими

- **Individual** — перший студент до першого репо, другий до другого, і так далі.
- **Team** — клікаєте студента і призначаєте його на спільне репо.

**Permission** (для org-репо): `pull`, `push`, `triage`, `maintain`, `admin`.  
Для особистих репо GitHub зазвичай дає write (`push`). Якщо поле permission відхилено, бекенд повторить запит без нього.

## Копіювання issues

Вкладка **Copy Issues**.

1. **Source repository** — звідки брати issues (`owner/template-lab`).
2. **Target repository** — куди копіювати (`owner/student-lab`).
3. За потреби увімкніть **Include closed issues** і **Keep closed issues closed**.
4. Що копіювати:
   - **All issues** — усі issues джерела (крім pull request-ів);
   - **Numbers / ranges** — конкретні номери або діапазони, наприклад `3`, `1-10`, `1-5, 8, 12-15`.
5. **Preview source issues** — список із галочками (клік по рядку теж оновлює поле номерів).
6. **Copy issues with labels**.

Що зберігається:

- заголовок і тіло issue;
- лейбли: якщо такого лейбла немає на цілі, він створюється з тим самим кольором і описом;
- стан closed — якщо опція увімкнена.

Pull request-и пропускаються. Якщо на цілі вже є issue з такою самою назвою, воно пропускається (skipped). У кінець тіла додається рядок `Copied from owner/repo#N`.

### Випадкові кольори лейблів

У тому ж розділі блок **Randomize label colors**. Вкажіть `owner/repo` (підставляється з Source, якщо вже заповнений) і натисніть **Randomize colors**. Кожен лейбл на цьому репозиторії отримує новий колір; issues лишаються з тими самими лейблами. Токен потребує **Issues: Read and write**.

## Типовий сценарій ментора без org

1. Токен з resource owner = ви.
2. Create: шаблон ваш або чужий template, **Target organization порожнє**.
3. Invite: **My account → Load from GitHub**, вибрати репо, вставити юзернейми студентів, **Send**.
